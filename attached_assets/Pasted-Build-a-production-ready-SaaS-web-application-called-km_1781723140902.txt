Build a production-ready SaaS web application called kmcheck.com.

1. Core Idea

A VIN lookup platform for cars that provides:

* Accident history
* Mileage history
* Car specifications
* Photos
* Market/auction data (when available)

Data is retrieved from external APIs (starting with: https://carstat.dev), with support for multiple future providers per country (e.g. USA = provider A, Korea = provider B).

Each country can have only one active provider at a time, configurable from admin dashboard.

7. VIN Data Logic (VERY IMPORTANT)

When a user requests a VIN:

1. Check internal database first
2. If exists → return instantly (no API call)
3. If not exists:
    * Call active API provider for that country
    * Normalize response format
    * Store result in database (cache it permanently)
    * Return to user

This system must:

* Prevent duplicate API calls
* Handle high traffic safely
* Include queue or caching strategy if needed
* Be optimized for concurrency (many users at once)
